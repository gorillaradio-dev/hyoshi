Setup locale

Procedura per portare il progetto da git clone a app funzionante in locale. Tempo realistico: ~10 minuti se hai già tutti i prerequisiti, ~20-30 se devi installarli.

Prerequisiti

  • PHP 8.3+ (preferito 8.4, allineato a CI/deploy)
  • Composer 2.x
  • Node 22+ con npm
  • MySQL 8 locale, utente root senza password
  • Git con accesso a gorillaradio-dev/hyoshi

Su macOS: brew install php@8.4 composer node@22 mysql@8.0. Su Linux: usa il package manager della distro o mise/asdf per gestire versioni multiple.

1. Clone

git clone git@github.com:gorillaradio-dev/hyoshi.git trainer-hub
cd trainer-hub

Il default branch è main. Vedi Branch strategy per la divisione tra main (trunk attivo + deploy a staging) e production (deploy futuro).

2. Database

Crea il database MySQL trainerhub. La connessione di default (.env.example) usa root senza password: 

mysql -uroot -e 'CREATE DATABASE trainerhub CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;'

3. Setup automatico

Lo script composer setup fa tutto il lavoro pesante in un comando: 

composer setup

Equivale a:

composer install
cp .env.example .env       # se non esiste già
php artisan key:generate
php artisan migrate --force
npm install
npm run build

Dopo questo passo hai: dipendenze installate, .env con APP_KEY, schema DB aggiornato, asset frontend buildati.

4. .env minimo

Apri .env e verifica/sovrascrivi i campi DB se non usi i default: 

APP_NAME=TrainerHub
APP_URL=http://localhost:8000

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=trainerhub
DB_USERNAME=root
DB_PASSWORD=

Non servono variabili Stripe per il setup base: il billing (Cashier) è predisposto ma non ancora attivo. Lo configurerai quando avvieremo lo Sprint 2.

5. Avvia l'ambiente di sviluppo

composer dev

Lancia in parallelo (con concurrently):

  • php artisan serve — backend su http://localhost:8000
  • php artisan queue:listen — worker queue
  • php artisan pail — tail dei log applicativi
  • npm run dev — Vite dev server con HMR

Output colorato, ogni processo ha il suo nome. Ctrl+C ferma tutto.

6. Crea il primo tenant

Apri http://localhost:8000, registrati (la registrazione Fortify è attiva di default), accedi. Verrai reindirizzato a /onboarding dove crei il tuo primo tenant — uno slug univoco per il "nome palestra".

Dopo l'onboarding sarai su /app/{slug}/dashboard. Da qui hai accesso a: Allievi, Gruppi, Pagamenti.

Reset completo

Se vuoi ricominciare da zero (DB pulito, niente tenant, niente dati): 

php artisan migrate:fresh
# poi rifai il flusso di registrazione + onboarding

Testing mobile

Per testare dal telefono col dev server: docs/mobile-testing.md spiega come esporre php artisan serve in LAN (--host=0.0.0.0) e configurare Vite per HMR via rete.

Problemi comuni

  • "Class not found" dopo pull → composer dump-autoload.
  • 500 dopo aggiornamento → php artisan optimize:clear.
  • Vite non hot-reloada → riavvia composer dev (a volte il watch perde i file).
  • Lint fallisce su file generati Wayfinder → resources/js/actions/** e resources/js/routes/** sono già in eslint.config.js ignores; se vedi errori lì, hai pulito la cache Wayfinder e il rebuild Vite ne ha rigenerati di nuovi — riavvia npm run dev.
  • "SQLSTATE access denied" → controlla che MySQL accetti root senza password (default su brew install mysql con brew services start mysql).
