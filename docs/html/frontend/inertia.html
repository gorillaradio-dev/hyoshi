Architettura Inertia

Inertia.js è il ponte tra Laravel e React in TrainerHub. Non c'è un'API REST separata: il backend risponde con il nome di un componente React e le sue props; il frontend lo monta come pagina. Risultato: ergonomia di una SPA (navigazione client-side, no full reload) con la semplicità di un'app server-rendered (zero gestione di token, validazione lato server, redirect HTTP).

Il modello mentale

Pensala così: ogni rotta Laravel è una "pagina". Il controller decide quale componente React renderizzare e con quali props. Il browser fa il primo render server-side, le navigazioni successive sono XHR Inertia che ricevono solo il payload props.

Flusso Inertia 
sequenceDiagram
  participant B as Browser
  participant L as Laravel
  participant I as Inertia middleware
  participant R as React
  B->>L: GET /app/{slug}/students/{id}
  L->>I: Inertia::render('Tenant/Student/Show', props)
  I->>B: HTML root + JSON payload (first load)
  Note over B: createInertiaApp().setup() monta React
  B->>R: resolvePageComponent('Tenant/Student/Show')
  R->>B: Pagina renderizzata
  B->>L: Link.click() / form submit (navigazione successiva)
  L->>I: render(...)
  I->>B: JSON payload (no full reload)
  B->>R: monta la nuova pagina

Entry point: app.tsx

File: resources/js/app.tsx. Inertia si avvia con createInertiaApp: il resolver mappa il nome del componente al file .tsx corrispondente in resources/js/pages/. 

createInertiaApp({
    title: (title) => (title ? `${title} - ${appName}` : appName),
    resolve: (name) =>
        resolvePageComponent(
            `./pages/${name}.tsx`,
            import.meta.glob('./pages/**/*.tsx'),
        ),
    setup({ el, App, props }) {
        const root = createRoot(el);
        root.render(
            <StrictMode>
                <App {...props} />
            </StrictMode>,
        );
    },
    progress: { color: '#1B7A3D' },
});

import.meta.glob è una feature di Vite: codifica al build-time il mapping nome→file, così il resolver è statico e tree-shakable.

Lato backend: Inertia::render

// Da app/Http/Controllers/Tenant/StudentController.php
return Inertia::render('Tenant/Student/Show', [
    'student'  => $student,
    'groups'   => Group::all(),
    'payments' => $paymentData,
]);

Il primo argomento è il nome relativo a resources/js/pages/ senza estensione. Il secondo è il payload di props (Eloquent → JSON automaticamente).

Shared props

Il middleware HandleInertiaRequests::share() condivide dati con ogni pagina, senza doverli passare esplicitamente dai controller. 

// app/Http/Middleware/HandleInertiaRequests.php
public function share(Request $request): array
{
    return [
        ...parent::share($request),
        'name' => config('app.name'),
        'auth' => ['user' => $request->user()],
        'sidebarOpen' => ! $request->hasCookie('sidebar_state')
            || $request->cookie('sidebar_state') === 'true',
        'tenant' => fn () => tenant() ? [
            'id'   => tenant('id'),
            'name' => tenant('name'),
            'slug' => tenant('slug'),
        ] : null,
    ];
}

Cosa è disponibile su ogni pagina via usePage().props:

PropTipoNote
auth.userUser o nullL'utente loggato.
tenantSharedTenant o nullIl tenant corrente (id/name/slug). Null sulle route centrali.
sidebarOpenbooleanStato persistito nei cookie.
namestringNome dell'app.

Accesso al tenant: useTenant()

Per leggere il tenant da un componente dentro una route tenant, usa l'hook useTenant(). È un wrapper attorno a usePage().props.tenant che lancia un errore se il tenant non c'è (== sei in una route central per sbaglio). 

// resources/js/hooks/use-tenant.ts
export function useTenant(): SharedTenant {
    const { tenant } = usePage().props;

    if (!tenant) {
        throw new Error('useTenant() must be used inside a tenant route.');
    }

    return tenant;
}

Uso tipico:

const tenant = useTenant();
const studentsUrl = `/app/${tenant.slug}/students`;

Costruire URL a mano è scomodo e fragile. Meglio: usare i route helper generati da Laravel Wayfinder in resources/js/routes/ — sono tipizzati e ricevono il tenant come parametro.

Form: useForm

Inertia React ha il proprio hook useForm che integra stato del form, submission, errori di validazione e progress. Usa sempre quello, mai useState manuale + fetch. 

import { useForm } from '@inertiajs/react';

const form = useForm({
    first_name: '',
    last_name: '',
    email: '',
});

function submit(e: FormEvent) {
    e.preventDefault();
    form.post('/app/' + tenant.slug + '/students', {
        onSuccess: () => form.reset(),
    });
}

// form.errors.first_name → messaggio di validazione dal backend
// form.processing → true durante la submit
// form.data → stato corrente
// form.setData('first_name', value)

Layout persistenti

Inertia supporta layout che non si smontano tra navigazioni nella stessa sezione (mantenendo state, scroll, focus). Ogni pagina dichiara il suo layout: 

// resources/js/pages/Tenant/Student/Show.tsx
import TenantLayout from '@/layouts/tenant-layout';

export default function StudentShow(props: Props) {
    // ...
}

StudentShow.layout = (page: ReactElement) => <TenantLayout>{page}</TenantLayout>;

Vedi Layout & navigazione mobile per TenantLayout nel dettaglio.

Server-Side Rendering

L'entry SSR è resources/js/ssr.tsx. Il comando npm run build:ssr produce il bundle SSR. Non attivo in deploy attuale, ma il file esiste per quando servirà.
