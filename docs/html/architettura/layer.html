Layer & moduli

Questa pagina è una mappa pratica del codebase: per ciascun layer applicativo trovi cosa contiene, i file chiave, e dove andare per approfondire. Pensala come una bussola da consultare quando ti chiedi "dove vive questa responsabilità?".

Per la vista architetturale a flusso (richieste, dipendenze tra layer) vai a Architettura · vista d'insieme. Per il modello dati vai a Modello dati.

HTTP / Controller

Lo strato sottile che riceve la richiesta, la valida e la passa al dominio.

  • app/Http/Controllers/Tenant/StudentController.php — gestione completa degli allievi: index con filtri, CRUD, sospendi/riattiva, ricerca.
  • app/Http/Controllers/Tenant/GroupController.php — CRUD dei gruppi con conteggio iscritti.
  • app/Http/Controllers/Tenant/StudentPaymentController.php — registrazione pagamenti mensili e di iscrizione.
  • app/Http/Controllers/Tenant/StudentGroupController.php — attach/detach gruppo-allievo.
  • app/Http/Controllers/Tenant/DashboardController.php — vista riepilogo del tenant.
  • app/Http/Controllers/Central/OnboardingController.php — onboarding del trainer: crea il tenant con slug univoco.
  • app/Http/Middleware/EnsureTenantAccess.php — guard ownership tenant (vedi Multi-tenancy).
  • app/Http/Middleware/HandleInertiaRequests.php — condivide auth, tenant e flash con il frontend.
  • app/Http/Requests/… — FormRequest per la validazione (Store/Update di Student, Group, ecc.).
  • routes/tenant.php · routes/web.php · routes/settings.php · routes/auth.php — le 4 file di route.

Approfondimenti: Routing, Controller & FormRequest, Policy.

Dominio / Service

La business logic — mai nei controller, sempre nei service.

  • app/Services/FeeCalculationService.php — tariffa effettiva (override → gruppo) e saldo studente.
  • app/Services/MonthlyFeeService.php — calcolo periodi scoperti, registrazione pagamenti FIFO, conteggi batch.
  • app/Services/EnrollmentFeeService.php — iscrizione e rinnovo, validità basata sui settings del tenant.
  • app/Enums/StudentStatus.php, PaymentMethod.php, DocumentType.php, DocumentStatus.php — backed enum PHP 8.1.
  • app/Policies/StudentPolicy.php, GroupPolicy.php — authorization per risorsa.
  • app/Providers/TenancyServiceProvider.php — mappa gli eventi del ciclo di vita del tenant ai listener.
  • app/Providers/AppServiceProvider.php — forza HTTPS in staging/production.

Approfondimenti: Quote & pagamenti, Iscrizioni, Enum di stato.

Dati

Modelli Eloquent, migrazioni, factory. Tutti i modelli tenant-scoped usano HasUuids + BelongsToTenant.

  • app/Models/Student.php — entità centrale del dominio (anagrafica, contatti, quote, gruppi, pagamenti).
  • app/Models/Group.php · GroupStudent.php — gruppi e pivot many-to-many.
  • app/Models/MonthlyFee.php · EnrollmentFee.php · Payment.php — quote attese e pagamenti effettivi.
  • app/Models/Document.php · EmergencyContact.php — documenti e contatti d'emergenza.
  • app/Models/Tenant.php · User.php — modelli centrali (non tenant-scoped).
  • database/migrations/ — una per tabella; le restructure_* più recenti collegano le quote a payments.
  • database/factories/ — factory per ogni modello (usate dai test).

Approfondimenti: Modello dati, Studenti e gruppi.

Frontend · Pagine

Componenti React Inertia. Mappa diretta con i controller backend.

  • resources/js/pages/Tenant/Student/Index.tsx — elenco allievi con filtri e pagamento rapido.
  • resources/js/pages/Tenant/Student/Show.tsx — dettaglio allievo (anagrafica, contatti, gruppi, pagamenti).
  • resources/js/pages/Tenant/Student/{Create,Edit}.tsx — form allievo.
  • resources/js/pages/Tenant/Group/{Index,Show,Create,Edit}.tsx — gestione gruppi.
  • resources/js/pages/Tenant/Dashboard/Index.tsx — dashboard del tenant.
  • resources/js/pages/Central/Onboarding/Create.tsx — creazione del primo tenant.
  • resources/js/app.tsx — entry point (risolve i componenti via resolvePageComponent).
  • resources/js/ssr.tsx — entry point Server-Side Rendering.

Frontend · Componenti & Layout

  • resources/js/components/student-form.tsx — form allievo con contatti dinamici e override quota.
  • resources/js/components/group-form.tsx — form gruppo.
  • resources/js/components/register-enrollment-dialog.tsx · student-payments-tab.tsx — UI pagamenti.
  • resources/js/components/page-header.tsx — header pagina con back button.
  • resources/js/components/tenant-{sidebar,mobile-header,bottom-nav}.tsx — chrome di navigazione.
  • resources/js/components/ui/ — primitivi shadcn/ui (button, input, dialog, …).
  • resources/js/layouts/{tenant-layout,central-layout}.tsx — layout persistenti Inertia.

Frontend · Hook, Utility, Type

  • resources/js/hooks/use-tenant.ts — accesso al tenant corrente da componenti tenant-scoped.
  • resources/js/hooks/use-appearance.ts — gestione tema chiaro/scuro.
  • resources/js/lib/utils.ts · student-status.ts — utility condivise.
  • resources/js/types/index.ts — barrel dei type-definition di dominio.
  • resources/js/types/student.ts — tipi Student/Group/Payment lato client.
  • resources/js/actions/ · resources/js/routes/ — generati da Laravel Wayfinder (escluse dal lint).

Test

  • tests/Feature/Tenant/*Test.php — feature test sui controller tenant (isolamento, CRUD, pagamenti).
  • tests/Feature/Tenant/PaymentEdgeCasesTest.php — riferimento per casi limite del denaro.
  • tests/Feature/Tenant/StudentLifecycleTest.php — copertura del refactor effective_status.
  • tests/Unit/Services/*Test.php — unit test sui service (calcoli, edge case puri).
  • tests/TestCase.php · Pest.php — boilerplate Pest.

Approfondimento: Testing.

Configurazione

  • config/tenancy.php — bootstrappers, identification, central domains. File critico.
  • config/fortify.php — feature di autenticazione (2FA, recovery codes).
  • config/database.php · config/session.php · config/cache.php — connessioni e storage.
  • vite.config.ts · tsconfig.json · eslint.config.js · composer.json — build e tooling.
  • CLAUDE.md — convenzioni di progetto (la fonte di verità sulle regole).

CI/CD

  • .github/workflows/deploy.yml — deploy SSH su push a main.
  • .github/workflows/tests.yml — Pest su PHP 8.4 e 8.5.
  • .github/workflows/lint.yml — Pint + ESLint + Prettier.
  • .github/workflows/sync-docs.yml — mirror di docs/html/ verso il portale centrale.
  • .github/workflows/claude.yml · claude-code-review.yml — review automatiche.

Approfondimenti: Deploy & CI/CD, Branch strategy.
