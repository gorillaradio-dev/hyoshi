Controller & FormRequest

I controller in TrainerHub sono thin: ricevono la richiesta validata, invocano la Policy, delegano il lavoro a un service, e restituiscono una pagina Inertia. Niente business logic dentro il controller. Niente query Eloquent complesse. Niente validazione inline.

Divisione delle responsabilità

CosaDove vive
Validazione inputapp/Http/Requests/Tenant/*Request.php (FormRequest)
Authorizationapp/Policies/*Policy.php + chiamata $this->authorize(...)
Business logicapp/Services/*Service.php
Persistenzaapp/Models/ (Eloquent)
Routing / orchestrazioneapp/Http/Controllers/ (qui dentro)

Esempio canonico: StudentController

Da app/Http/Controllers/Tenant/StudentController.php. Mostra il pattern completo: authorize → query con filtri → response Inertia. 

public function index(Request $request)
{
    $this->authorize('viewAny', Student::class);

    $query = Student::with('phoneContact');

    if ($search = $request->input('search')) {
        $query->where(function ($q) use ($search) {
            $q->where('first_name', 'like', "%{$search}%")
              ->orWhere('last_name', 'like', "%{$search}%")
              ->orWhere('email', 'like', "%{$search}%");
        });
    }

    // ...filtri stato (active/pending/suspended/all)

    $students = $query->orderBy('last_name')->paginate(20);

    return Inertia::render('Tenant/Student/Index', [
        'students' => $students,
        'filters' => $request->only(['search', 'status']),
    ]);
}

Note sul pattern:

  • Student::with('phoneContact') — eager loading per evitare N+1 in vista.
  • Il global scope tenant è già applicato: nessuna where('tenant_id', ...) a mano.
  • Il response è Inertia::render('Pagina', props) — niente JSON, niente Blade view.

FormRequest: validazione dichiarativa

I controller ricevono FormRequest tipizzati. Tutta la validazione, normalizzazione e autorizzazione di campo vive nella request, mai inline nel controller. 

// app/Http/Requests/Tenant/StoreStudentRequest.php
public function authorize(): bool
{
    return true; // autorizzazione gestita dal middleware tenant.access
}

public function rules(): array
{
    return [
        'first_name' => ['required', 'string', 'max:255'],
        'last_name'  => ['required', 'string', 'max:255'],
        'email' => [
            'nullable', 'email', 'max:255',
            Rule::unique('students')->where('tenant_id', tenant()->getTenantKey()),
        ],
        'phone' => ['nullable', 'string', 'max:50'],
        'date_of_birth' => ['nullable', 'date', 'before:today'],
        'fiscal_code'   => ['nullable', 'string', 'max:16'],
        'address' => ['nullable', 'string', 'max:500'],
        'emergency_contacts'         => ['nullable', 'array', 'max:5'],
        'emergency_contacts.*.name'  => ['required', 'string', 'max:255'],
        'emergency_contacts.*.phone' => ['required', 'string', 'max:50'],
        'phone_contact_index'        => ['nullable', 'integer'],
        'notes' => ['nullable', 'string', 'max:5000'],
        'enrolled_at' => ['nullable', 'date'],
        'monthly_fee_override' => ['nullable', 'numeric', 'min:0'],
    ];
}

protected function prepareForValidation(): void
{
    // Converte euro decimali (€50.00 dalla UI) in centesimi (5000) prima della validazione
    if ($this->has('monthly_fee_override') && $this->monthly_fee_override !== null && $this->monthly_fee_override !== '') {
        $this->merge([
            'monthly_fee_override' => (int) round($this->monthly_fee_override * 100),
        ]);
    }
}

prepareForValidation() è il punto giusto per normalizzare i dati prima delle regole: trim, lowercase, conversione euro→centesimi, ecc. Non sporcare le rules con cast logici.

Validazione unique tenant-aware

Le regole unique devono essere esplicitamente scoped al tenant, perché Laravel non lo fa automaticamente: 

Rule::unique('students')->where('tenant_id', tenant()->getTenantKey())

Senza il where, un'email duplicata in due tenant diversi farebbe fallire la validazione anche se i tenant non si vedono. Errore comune che il global scope NON previene perché agisce su Eloquent, non sul query builder usato da Rule::unique.

Pattern ricorrenti

Store

public function store(StoreStudentRequest $request)
{
    $this->authorize('create', Student::class);

    $student = Student::create($request->validated());
    // ...gestione collegamenti opzionali (emergency contacts, gruppi)

    return redirect()->route('tenant.students.show', [
        'tenant'  => tenant()->slug,
        'student' => $student->id,
    ])->with('success', 'Allievo creato.');
}

Azione personalizzata (sospendi)

public function suspend(Student $student)
{
    $this->authorize('update', $student);

    // delega al modello o al service (qui semplice update)
    $student->update(['status' => StudentStatus::Suspended]);

    return back()->with('success', 'Allievo sospeso.');
}

Delega a service per logica monetaria

public function registerMonthly(
    RegisterMonthlyPaymentRequest $request,
    Student $student,
    MonthlyFeeService $monthlyFeeService,
) {
    $this->authorize('update', $student);

    $payment = $monthlyFeeService->registerPayment(
        $student,
        $request->integer('months'),
        $request->integer('amount'),
        $request->input('notes'),
    );

    return back()->with('success', "Pagamento registrato (€".number_format($payment->amount / 100, 2).").");
}

Il controller fa una sola cosa: orchestra. Il calcolo dei periodi, la creazione delle MonthlyFee, il rispetto del FIFO — tutto dentro MonthlyFeeService.

Risorse Inertia: pagine, non JSON

I controller non rispondono mai con JSON (tranne casi di endpoint dati per autocomplete, es. StudentController::search che ritorna JSON nudo). Per le pagine la response è sempre: 

return Inertia::render('Tenant/Student/Show', [
    'student'    => $student,
    'groups'     => Group::all(),
    'paymentData' => $paymentService->buildFor($student),
]);

Il primo argomento è il nome del componente React in resources/js/pages/; il secondo è il payload di props. Vedi Architettura Inertia per come il frontend riceve e monta.

Checklist per un nuovo controller tenant

  • Estende App\Http\Controllers\Controller (per AuthorizesRequests).
  • Ogni metodo chiama $this->authorize(...) con la Policy giusta.
  • Validazione in una FormRequest in app/Http/Requests/Tenant/.
  • Business logic in un service dedicato (mai inline).
  • Response Inertia con props tipizzate lato frontend (vedi resources/js/types/).
  • Feature test in tests/Feature/Tenant/ che includa la verifica di isolamento.
