Pagine principali

Le pagine React di TrainerHub vivono in resources/js/pages/ e mappano 1-a-1 con i controller backend. Questa pagina è un tour ragionato: per ciascuna sezione, le pagine che la compongono e i pattern che vedrai più spesso (filtri persistiti, debounce search, tab, modal di azione).

Organizzazione

resources/js/pages/
├── Welcome.tsx                 — landing page pubblica
├── Auth/                       — login, register, password reset (Fortify)
├── Settings/                   — profilo, password, 2FA, appearance
├── Central/
│   └── Onboarding/Create.tsx   — creazione del primo tenant
└── Tenant/                     — tutto sotto /app/{slug}/
    ├── Dashboard/Index.tsx
    ├── Student/
    │   ├── Index.tsx           — elenco con filtri, pagamento rapido
    │   ├── Show.tsx            — dettaglio con tab
    │   ├── Create.tsx          — form nuovo
    │   └── Edit.tsx            — form modifica
    └── Group/
        ├── Index.tsx
        ├── Show.tsx            — dettaglio + membri
        ├── Create.tsx
        └── Edit.tsx

Convenzione di naming: directory PascalCase singolare (Student/, non Students/), file PascalCase (Index.tsx, Show.tsx, Create.tsx, Edit.tsx).

Dashboard (Tenant/Dashboard/Index.tsx)

Vista riepilogo del tenant: KPI principali, allievi in stato di attenzione (quote scoperte, iscrizione in scadenza), shortcut alle azioni più frequenti. È la prima pagina che vede il trainer dopo il login.

Elenco allievi (Tenant/Student/Index.tsx)

La pagina più usata: tabella allievi con filtro per stato (active/pending/suspended/all), ricerca testuale, conteggio quote scoperte per riga, e azione "pagamento rapido" che apre un dialog senza navigare via.

  • Filtri persistiti via URL — i parametri ?search=...&status=... sono nel querystring; refresh o copy-paste conservano lo stato.
  • Quote scoperte indicate visivamente — un badge rosso accanto al nome quando uncovered_count > 0 (dato calcolato batch lato server).
  • Pagamento rapido — vedi register-monthly-dialog.tsx: aperto dalla riga, registra un pagamento mensile senza lasciare la pagina.

Dettaglio allievo (Tenant/Student/Show.tsx)

Pagina ricca, organizzata in tab (shadcn Tabs):

TabContenuto
AnagraficaDati personali, contatti, codice fiscale, indirizzo.
Gruppistudent-groups-card.tsx: attach/detach gruppi, designazione gruppo primario.
Pagamentistudent-payments-tab.tsx: storico pagamenti mensili + iscrizioni, saldo, registra nuovo pagamento.

Azioni principali: Modifica (→ Edit.tsx), Sospendi (PUT /suspend), Registra iscrizione (dialog), Registra pagamento mensile (dialog).

Form allievo (Tenant/Student/{Create,Edit}.tsx)

Entrambe le pagine usano resources/js/components/student-form.tsx condiviso. Pattern notabili:

  • Contatti d'emergenza dinamici — array di righe con useFieldArray-style: aggiungi/rimuovi righe, designi un contatto come "telefono principale" via phone_contact_index.
  • Override quota — campo numerico in euro lato UI; la conversione a centesimi avviene in StoreStudentRequest::prepareForValidation() (vedi Controller & FormRequest).
  • Validazione lato server — gli errori arrivano da form.errors di Inertia; visualizzati con input-error.tsx.

Gruppi (Tenant/Group/Show.tsx)

Dettaglio gruppo con elenco membri. Pattern interessante: ricerca debounced per aggiungere studenti, evitando di hammerare il server a ogni keypress (usa il sub-endpoint tenant.students.search che ritorna JSON).

Pattern ricorrenti

Form con useForm

const form = useForm({
    first_name: '',
    last_name: '',
    email: '',
});

form.post('/app/' + tenant.slug + '/students', {
    onSuccess: () => form.reset(),
    preserveScroll: true,
});

preserveScroll: true è utile quando il form sta in fondo a una pagina lunga e un errore di validazione farebbe scrollare via.

Dialog di azione

Pattern shadcn Dialog: il bottone trigger sta nella riga della tabella o nell'header pagina, il DialogContent è un useForm per l'azione (es. register-monthly-dialog.tsx). Submit ottimistico: chiudere il dialog in onSuccess, mostrare flash via toast.

Header pagina riutilizzabile

resources/js/components/page-header.tsx mette title, descrizione, back button e action slot in modo consistente. Usalo invece di rifare l'header in ogni pagina.

Empty state

Quando una collection è vuota (es. nessuno studente, nessun pagamento), mostra una empty state con copy chiaro e azione primaria (es. "Aggiungi il primo allievo"). Non lasciare tabelle vuote.

Stato di caricamento

Inertia gestisce il progress bar globale (vedi app.tsx: progress: { color: '#1B7A3D' }). Per azioni puntuali, usa form.processing per disabilitare i bottoni durante la submit.

"Dove aggiungo una nuova pagina?"

  1. Decidi se è tenant o central (vedi Routing).
  2. Crea il file in resources/js/pages/Tenant/<Resource>/<Action>.tsx.
  3. Esporta default + assegna il layout: Page.layout = (p) => <TenantLayout>{p}</TenantLayout>.
  4. Dal controller, return Inertia::render('Tenant/<Resource>/<Action>', $props).
  5. Aggiungi la route in routes/tenant.php con il middleware giusto.
  6. Aggiungi una entry nella sidebar (resources/js/components/tenant-sidebar.tsx) se è una pagina principale, oppure raggiungibile da link interno se è secondaria.
