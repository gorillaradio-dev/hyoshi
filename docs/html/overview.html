Panoramica

TrainerHub è un gestionale multi-tenant pensato per i personal trainer: ogni trainer (tenant) gestisce in autonomia i propri studenti, le quote mensili e i pagamenti, con i dati completamente isolati dagli altri tenant.

Cos'è

L'obiettivo è dare al trainer un unico posto da cui seguire gli studenti e tenere sotto controllo gli incassi. Il prodotto è mobile-first: il trainer lo usa spesso dal telefono, a bordo campo o in palestra.

Stack tecnologico

  • Backend: Laravel 12 (PHP 8.3)
  • Frontend: React 19 + Inertia.js 2.x + TypeScript (Laravel React Starter Kit)
  • UI: shadcn/ui + Tailwind CSS 4
  • Multi-tenancy: stancl/tenancy v3 in modalità single-database
  • Billing: Laravel Cashier (Stripe)
  • Database: MySQL 8

Architettura multi-tenant

TrainerHub usa un singolo database con una colonna discriminante tenant_id su ogni tabella tenant-scoped. Il tenant corrente è risolto dal path della URL: le route tenant vivono sotto /app/{tenant:slug}/….

  • I modelli tenant-scoped usano il trait BelongsToTenant, che applica un global scope automatico e assegna tenant_id in fase di creazione.
  • L'accesso ai dati di un tenant passa sempre dal global scope: un tenant non può mai vedere i dati di un altro.
  • Lo stack di middleware delle route tenant è identify.tenant → tenant.access → subscribed.

Concetti chiave

  • Tenant — il personal trainer e il suo spazio dati isolato.
  • Student — lo studente seguito dal trainer.
  • Monthly fee — la quota mensile dovuta dallo studente; gli importi monetari sono salvati come interi in centesimi (es. 5000 = €50,00).

Convenzioni

Codice, nomi e commenti sono in inglese; le label e i messaggi rivolti all'utente sono in italiano. Gli ID sono UUID ovunque.
