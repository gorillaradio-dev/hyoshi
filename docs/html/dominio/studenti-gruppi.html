Studenti e gruppi

Lo studente (allievo) è l'entità centrale del dominio. Vive dentro un tenant, ha una serie di contatti d'emergenza, può appartenere a uno o più gruppi (corsi/discipline), e accumula quote mensili e iscrizioni nel tempo.

Il modello Student

File: app/Models/Student.php. Usa HasUuids, BelongsToTenant e SoftDeletes: ogni studente è UUID, scoped al tenant, e può essere cancellato solo "logicamente".

Relazioni

  • emergencyContacts(): HasMany — contatti d'emergenza.
  • phoneContact(): BelongsTo — quale contatto usare come telefono principale.
  • enrollmentFees(): HasMany — iscrizioni annuali.
  • monthlyFees(): HasMany — quote mensili attese.
  • payments(): HasMany — pagamenti effettivi.
  • documents(): HasMany — certificati, privacy, ID.
  • groups(): BelongsToMany — gruppi a cui appartiene (via pivot).

Stato effettivo

Lo stato visibile dello studente (effective_status) è in parte calcolato. La colonna status sul DB serve solo a memorizzare Suspended; tutto il resto è derivato in tempo reale dall'iscrizione corrente. 

// Student::effectiveStatus accessor
if ($this->status === StudentStatus::Suspended) {
    return StudentStatus::Suspended->value;
}

$enrollmentService = app(EnrollmentFeeService::class);
if ($enrollmentService->hasValidEnrollment($this)) {
    return StudentStatus::Active->value;
}

return StudentStatus::Pending->value;

Questo refactor è stato introdotto in docs/plans/2026-04-09-student-lifecycle-refactor.md: prima lo stato era interamente persistito e si "desincronizzava" facilmente. Ora la sola fonte di verità dell'attività è l'esistenza di un'iscrizione valida.

File: app/Models/Group.php. Rappresenta un corso/disciplina/gruppo di allenamento. Tenant-scoped, UUID.

La pivot group_student

Il legame studente↔gruppo è many-to-many con una pivot dedicata: group_student. Modellata come App\Models\GroupStudent (estende Pivot), tenant-scoped e UUID per coerenza con il resto del dominio. 

// Group::students
return $this->belongsToMany(Student::class, 'group_student')
    ->using(GroupStudent::class)
    ->withPivot('is_primary')
    ->withTimestamps();

Il flag is_primary sulla pivot indica il gruppo principale dell'allievo, usato per default in UI quando va mostrato "un solo gruppo" (es. nel badge della riga elenco).

Contatti d'emergenza

EmergencyContact (tenant-scoped, UUID) appartiene a uno Student. Uno di questi può essere designato come "contatto telefonico principale" via students.phone_contact_id: l'accessor effective_phone ritorna il suo numero, oppure il phone diretto dello studente come fallback.

Ciclo di vita

  1. Creazione — anagrafica via StoreStudentRequest + StudentController::store.
  2. Iscrizione — almeno una EnrollmentFee registrata: lo stato passa a Active.
  3. Pagamenti mensili — quote dovute calcolate da current_cycle_started_at; MonthlyFeeService::registerPayment le marca FIFO.
  4. Iscrizione scaduta — torna a Pending automaticamente.
  5. Sospensione manuale — endpoint PUT students/{id}/suspend imposta status = Suspended e annota il ciclo in past_cycles.
  6. Riattivazione — PUT students/{id}/reactivate rimuove la sospensione.
  7. Cancellazione — soft delete (la riga resta sul DB con deleted_at valorizzato).

Per la sequenza completa degli stati vedi StudentStatus. Per il calcolo dei mesi dovuti vedi Quote mensili e pagamenti.
